## Summary

Dream Maker has grown from a bilingual emoji explorer into an account-backed creative workspace. v0.8.0 adds an editable emoji canvas, optional AI text generation, saved Creations and persistent temporary history, four themes, and username/password accounts with invitation activation. Preferences, Discovery favorites/history, creations, and generation attempts now live in SQLite rather than active browser storage. It remains a self-hostable Next.js application; public hosting and a deployment pipeline are not delivered by this tag.

### Progress since v0.2.0

The comparison includes **44 commits**, **15 merged PRs (#9–#23)**, and **163 changed files**.

- **Playground editor:** compose scenes with up to 80 emoji instances; add by click, keyboard, mouse drag, or touch. Pan, zoom, fit, and enter fullscreen. Select individual painted shapes or an area, move groups, resize, rotate, copy/paste, change stacking order, and undo/redo completed edits. Locally bundled Noto COLRv1 artwork remains sharp at different sizes. ([#9](https://github.com/juandarr/emoji-dream-maker/pull/9), [#15](https://github.com/juandarr/emoji-dream-maker/pull/15))

Requests include authored context and canvas placement, size, rotation, and stacking cues; titles and bodies follow the selected output language. Results support reading, editing, copying, and usage/model metadata. ([#10](https://github.com/juandarr/emoji-dream-maker/pull/10), [#13](https://github.com/juandarr/emoji-dream-maker/pull/13), [#18](https://github.com/juandarr/emoji-dream-maker/pull/18))
- **Creations and checkpoints:** save canvas-only, configured, or completed states; browse canvas → configuration → result groups; restore all or selected components with original-input provenance. Saved versions are immutable. Temporary history and saved membership are independent and have no retention cap. Bulk deletion has a five-second Undo window; failed saves retain visible work, and stale revisions require explicit resolution. ([#22](https://github.com/juandarr/emoji-dream-maker/pull/22), [#23](https://github.com/juandarr/emoji-dream-maker/pull/23))

Seven-day sessions, guarded application APIs, account ownership, same-origin mutations, and database-backed authentication limits are implemented. Account data survives logout, browser changes, and server restarts. ([#23](https://github.com/juandarr/emoji-dream-maker/pull/23))
- **Durable generation lifecycle:** persist the account checkpoint before contacting OpenRouter, store server completion even after browser disconnection, and deduplicate terminal requests by account/request ID. Cancellation and deletion prevent late results from resurrecting removed history. Startup marks interrupted requests unknown without resubmission; persistence Retry writes an already-received outcome without calling the provider again. ## Interface

Unauthenticated visitors see login/registration; inactive accounts see the waiting room; activated accounts enter Discover and Playground. Account preferences initialize language/theme before editing. Discovery includes Favorites and History, while Playground provides its Creations library, context/settings panels, canvas controls, and generated-result reader.

Switching tabs retains the working editor; a full refresh opens a blank editor while both creation collections remain available. Save/Discard/Cancel protects unsaved work during replacement and logout. Saving and failure states remain visible, conflicts preserve drafts, and logout clears the account workspace. The UI supports desktop and narrow-phone layouts, touch gestures, labeled keyboard editing, Escape dismissal, and modal focus restoration. Rectangular focus outlines were intentionally removed; constellation target-size findings caused by accepted emoji overlap are excluded from the documented accessibility audit, so this is not an unqualified accessibility-conformance claim.

## Services and data

| Service or storage | Configuration and verification |
| --- | --- |
| Better Auth / SQLite | Better Auth 1.7.7 and better-sqlite3 13.0.3 provide accounts and persistent local storage. Required server settings: `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `ACCOUNT_DB_PATH`, `INVITATION_PHRASE`, and `INVITATION_EMOJI_ID`. HTTPS enables Secure, HttpOnly, SameSite=Lax cookies. Three application migrations and Better Auth migrations run at startup. Account tests use isolated databases and real local authentication. |
| OpenRouter | Optional private `OPENROUTER_API_KEY`; configure allowed models, reasoning effort, and completion budget. The default model is `openrouter/free`, but this version also permits configured paid models. Generation sends authored scene/context and settings to the provider. Tests simulate provider responses and do not verify a live key or submit paid requests. |
| Wikimedia / Wikipedia | No API key; configure a valid server-side `WIKIMEDIA_USER_AGENT`. Resolution/context/related-article behavior continues from v0.2.0 with authenticated app access. No new live audit was performed for v0.8.0. |
| Cleveland Museum of Art / The Met | Public-domain artwork metadata, previews, attribution, and larger-image viewers continue. No new live museum audit was performed for this release. |
| YouTube | yt-dlp executable/Python worker with optional private `YOUTUBE_API_KEY` fallback. Metadata-only retrieval and bounded cache continue; external playback and current provider availability are not established by browser fixtures. |
| Freesound | Optional private `FREESOUND_API_KEY`; licensed previews and attribution continue. No fresh credentialed search or audio audition was performed. |
| GIPHY | Optional intentionally public `NEXT_PUBLIC_GIPHY_API_KEY`; searches/media remain browser-direct. No fresh authenticated audit. The existing README limitation concerning custom ranking/filtering and production integration remains. |

SQLite stores account/session data, validated preferences/Discovery state, creation payloads, revision/deletion metadata, and the durable generation-attempt ledger. Account ownership is derived from the session. Existing localStorage/IndexedDB records are left untouched and are not imported into accounts. Browser memory holds the active editor; this is not continuous collaborative or offline synchronization.

## Limits and planned work

- **Upgrade requirement:** Node.js 22+ (24 recommended), a working native SQLite binding, all five required account variables, and a private absolute persistent database path. The previous credential-free local-start procedure is no longer sufficient. Back up before schema upgrades; preserve the database and authentication secret across releases.
- **Deployment boundary:** one long-running Node process on persistent local disk. No public deployment, CI/CD, serverless/edge support, or multi-process generation coordination is provided by this tag. Use the SQLite online backup procedure rather than copying only an actively written database file.
- **Admission and recovery:** phrase/emoji activation is permanent; there are no email, password-recovery, or administration flows. Legacy browser data is not automatically migrated.
- **Generation limits:** two concurrent requests and six new starts per minute globally, plus four starts per account per minute. Provider calls have a 120-second deadline. Durable checkpoints do not make generation a background queue: shutdown can interrupt work, and unknown outcomes are never automatically resubmitted.
- **Creative scope:** one scene, no collaborative editing or offline merge, and text outputs only. Lyrics do not synthesize audio; image prompts/storyboards do not render images or video.
- External quotas, content relevance, embedding permission, free-model availability, and the documented GIPHY integration limitation remain. Planned work includes production delivery and future rendered-media/search capabilities.
